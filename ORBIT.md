# Orbit — contexte complet du projet

> Fichier de reprise : tout ce qu'il faut savoir pour continuer Orbit sur une autre machine (humain ou Claude Code).
> Dernière mise à jour : 5 octobre 2026.

## 1. Le produit en une phrase

**Orbit est un fork de VS Code (Code - OSS 1.140.0) construit autour de Claude Code qui tourne dans de vrais terminaux intégrés**, avec une identité visuelle spatiale (planète violette, lune menthe), un écran de chargement animé et une personnalisation poussée.

Ce n'est **pas** « un Cursor de plus » : l'IA n'est pas un chat greffé, c'est le vrai CLI `claude` dans des terminaux qu'on organise (onglets, splits, grille d'agents, worktrees), avec un IDE qui *sait* ce que fait chaque agent (statut en direct via les hooks de Claude Code).

## 2. Préférences et décisions de l'utilisateur (à respecter)

- **Tout en terminaux.** L'utilisateur a explicitement rejeté un chat webview séparé : « je veux que ce soit un clone du terminal… ça fonctionne que en terminaux exactement comme ici ».
  - Exception validée : la **« vue discussion »** est un *habillage* du MÊME terminal (même process `claude`, même session) — elle lit le transcript et renvoie la saisie dans le terminal. Bascule ⌥⌘T.
- **Facturation = abonnement Claude (Max)**, jamais le paiement à l'usage : Orbit retire `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` de l'environnement des terminaux Claude (réglage `orbit.claude.billing`).
- Claude ne doit pas produire d'**artefacts hébergés** : Orbit lance `claude --disallowedTools Artifact` + une consigne système « crée de vrais fichiers dans le dossier courant ».
- Langue de l'utilisateur : **français**. Interface du fork en anglais (strings VS Code), textes Orbit en français.
- Commits / PR : **aucune mention de Claude** (pas de `Co-Authored-By: Claude`, pas de « Generated with Claude Code »). Auteur : Jahid Sayad.
- Clavier Mac **AZERTY** : ne jamais activer `terminal.integrated.macOptionIsMeta` (casse `@ { [ |`).
- Visuels générés avec **Higgsfield** (logo, fond d'écran) — l'utilisateur aime les rendus « ultra beaux, vendeurs ».

## 3. Installation sur un nouveau PC (macOS arm64)

```bash
git clone https://github.com/jahid611/orbit-ide.git
cd orbit-ide
nvm install 24.18.0 && nvm use 24.18.0     # version exigée par .nvmrc
npm ci                                      # ~10-20 min, ~2 Go
npm run compile                             # ~1 min (tsgo)
./scripts/code.sh ~/un-projet               # lance Orbit en mode dev
```

Pré-requis : Xcode Command Line Tools, Python 3, git, **Claude Code installé et connecté** (`claude` puis `/login`).

### Construire l'application `Orbit.app`

```bash
NODE_OPTIONS=--max-old-space-size=8192 npm run gulp vscode-darwin-arm64-min   # ~2 min
# résultat : ../VSCode-darwin-arm64/Orbit.app
mv ../VSCode-darwin-arm64/Orbit.app /Applications/
codesign --force --deep -s - /Applications/Orbit.app    # signature ad-hoc
rm -rf out-vscode-min                                    # artefacts intermédiaires (régénérables)
```

Il faut ~1,5 Go libres pour un build (l'ancienne machine était à ~3-4 Go libres : surveiller le disque).

### Installation sur Windows (x64)

Pré-requis : Git, **Node 24.18.0** (une archive portable suffit, pas besoin de remplacer le Node du système), Python 3, Visual Studio Build Tools 2022 avec la charge « C++ » **et** le composant « Bibliothèques MSVC avec atténuation Spectre » (sans lui les modules natifs ne compilent pas), Claude Code installé et connecté.

```powershell
git clone https://github.com/jahid611/orbit-ide.git
cd orbit-ide
$env:PATH = "C:\chemin\vers\node-v24.18.0-win-x64;" + $env:PATH
npm ci
npm run compile
.\scripts\code.bat C:\un-projet
```

Particularités Windows gérées par l'extension :

- Les terminaux Claude sont toujours des **PowerShell** (la ligne de commande est écrite pour lui), quel que soit le shell par défaut.
- `claude` est résolu vers le vrai `claude.exe` derrière le raccourci npm `claude.cmd` (`resolveClaudeExecutable`).
- Les hooks passent par Git Bash, que Claude Code exige déjà sous Windows.
- Notifications : toast Windows via PowerShell (sous l'identité de PowerShell tant qu'Orbit n'est pas installé avec son raccourci).
- Icônes : `resources/win32/code.ico`, `code_150x150.png`, `code_70x70.png` (générées depuis `brand/orbit-icon-1024.png`).

### Après une modification

- Extension Orbit seule : `npm run gulp compile-extension:orbit` puis « Developer: Restart Extension Host ».
- Cœur (src/) : `npm run compile` puis **redémarrer complètement** la fenêtre (un simple Reload garde parfois l'ancien JS en cache).
- Pour tester sans toucher au profil perso : `./scripts/code.sh ~/projet --user-data-dir ~/.orbit-shot/ud --extensions-dir ~/.orbit-shot/ext --remote-debugging-port=9447` (le chemin du profil doit rester court, sinon le socket IPC échoue ; éviter les ports déjà pris).

### Publier une version

1. Monter `orbitVersion` dans `product.json` (c'est la version d'Orbit ; `version` dans `package.json` reste celle de VS Code).
2. Pousser, puis pousser l'étiquette `v<orbitVersion>` : `.github/workflows/orbit-release.yml` construit l'installateur Windows (`OrbitSetup-x64-<version>.exe`, Inno Setup, tâches `vscode-win32-x64-min` → `-inno-updater` → `-user-setup`) et l'archive macOS Apple Silicon (`Orbit-mac-arm64-<version>.zip`, signature ad hoc), et les attache à une version GitHub créée en **brouillon** avec le texte de `.github/orbit-release-notes.md`. La publier à la main une fois vérifiée.
3. En local, mêmes tâches gulp ; l'installateur sort dans `.build/win32-x64/user-setup/OrbitSetup.exe` (≈ 250 Mo, 4 min de compression).

Rien n'est signé (pas de certificat) : Windows affiche SmartScreen, macOS demande « Ouvrir quand même ». Les images de l'assistant d'installation (`resources/win32/inno-*.bmp`) sont faites depuis `brand/orbit-icon-1024.png`. Les automatisations GitHub héritées de Microsoft (tests sur leurs machines, Dependabot) ont été retirées le 9 octobre 2026.

**Mises à jour** (`extensions/orbit/src/update.ts`) : pas de serveur de mise à jour ; Orbit lit la dernière version publiée sur GitHub (45 s après le démarrage puis toutes les 6 h, réglage `orbit.update.mode`, commande `orbit.update.check`), compare à `orbitVersion`, annonce une fois par version. Sous Windows « Mettre à jour » télécharge l'installateur, un petit guetteur PowerShell attend la fermeture d'Orbit, installe sans question et rouvre Orbit. Sous macOS et Linux la page de téléchargement s'ouvre. Lancé depuis les sources (`VSCODE_DEV`), rien n'est vérifié. **Jamais exercé de bout en bout** tant qu'une deuxième version n'a pas été publiée.

| Son (8 octobre 2026) | **Volume d'écoute** dans la barre de lecture (haut-parleur + curseur, aussi en plein écran) : réglage du lecteur, gardé d'un montage à l'autre, jamais exporté (`engine.volume`). **Son d'une vidéo depuis le clip vidéo** : l'onglet Audio de l'inspecteur règle le clip de son lié à l'image (volume, fondus, couper, 0 dB, en fond, « Détacher » qui retire le lien). Compilé, pas vu à l'écran. |
| Export : décodage ciblé (8 octobre 2026) | Chaque décodeur saute à son premier clip (`-ss` avant `-i`, une seconde de marge) et s'arrête après son dernier (`-t`) ; des clips qui se suivent à moins de 12 s dans la source partagent encore un décodeur (`NEAR`), les temps de `trim` sont comptés depuis ce saut (`Segment.seek`). Avant, chaque source était lue depuis son début : un montage de passages courts pris dans des vidéos de 15 et 20 minutes les décodait en entier. Mesuré sur le montage de l'utilisateur (126 s, 1080p60, 33 clips étalonnés) : 10 min avant, 4 min 10 après ; images identiques à l'ancien rendu sur 12 s (PSNR minimum 53 dB). Le reste du temps est la chaîne de filtres sur le processeur (vignette, eq, calques), l'encodage étant déjà sur la carte graphique. |
| Export : rendu par parties (8 octobre 2026) | `exportProject` découpe le film en parties d'environ 8 s, coupées de préférence là où un clip vidéo commence (jamais dans une transition), rendues par `renderRange` à raison d'un quart des cœurs à la fois (3 au plus), le son étant rendu une fois en entier ; les parties sont jointes sans réencodage (`concat`, `-c copy`). Chaque partie a un nombre d'images imposé (`frames`, `-frames:v` + `tpad`) : la somme fait exactement le film. Raison : un seul graphe pour tout le film ouvre tous les décodeurs en même temps et leurs images s'entassent en mémoire. Le vignettage des vidéos est un masque noir dessiné une fois et superposé (le filtre `vignette` de ffmpeg coûtait un tiers du temps ; écart mesuré : PSNR moyen 49 dB). ffmpeg tourne en priorité basse (`run` dans `ffmpeg.ts`). **Mesures sur le montage de l'utilisateur (128,6 s, 1080p60, 33 clips étalonnés)** : 10 min à l'origine, 4 min 10 avec le décodage ciblé seul, **61 s** par parties (40 % de mémoire, processeur chargé mais en priorité basse). Six parties à la fois avait saturé la machine (98 % processeur, 93 % mémoire) : ne pas remonter ce nombre. Le rendu en un bloc (`STARCAPTURE_EXPORT_PARTS=0`, ProRes, WebM, films de moins de 12 s) prend un léger retard d'image à chaque clip (chaque morceau du `concat` est arrondi à l'image supérieure) ; le rendu par parties repart juste à chaque partie. Sans encodeur matériel, même chemin avec libx264. Les effets restent calculés par le processeur : c'est ce qui sépare encore des 20 s de CapCut. |
| Barre de progression | Sous l'image (`#scrub`, bord haut de la barre de lecture), dans la fenêtre comme en plein écran : tout le montage de gauche à droite, clic ou glisser pour aller à un moment, bulle avec le temps visé ; la lecture reprend au relâchement si elle était en cours. |
| Créations | Bibliothèque personnelle hors projet (`src/creations.ts`, `~/.orbit/starcapture/creations.json`) : effets, styles de texte, incrustations (filigrane), enregistrés par l'utilisateur ou par l'agent (`sc_creations`, `sc_creation_save`, `sc_creation_apply`, `sc_creation_delete`), onglet « Créations ». Essayé de bout en bout par les outils de l'agent le 9 octobre 2026 (enregistrer un effet, un style de texte, un filigrane ; appliquer ; annuler ; supprimer) ; l'onglet lui-même n'a pas été vu à l'écran. |
| Divers | Enregistrement automatique 1,5 s après toute modification (annuler/rétablir compris). L'export écrit `.<nom>.rendu.mp4` puis renomme : rien n'ouvre une vidéo à moitié écrite (Orbit n'ouvre plus automatiquement les médias créés). ### 4.3 Fonctionnement des hooks (statut des agents)

1. Chaque `claude` lancé par Orbit reçoit `--settings ~/.orbit/claude-settings.json`, qui déclare des hooks `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Notification`, `Stop`, `SessionEnd`.
2. Chaque terminal Claude reçoit un identifiant dans la variable d'environnement `ORBIT_TERMINAL_ID`. Le hook `~/.orbit/hook.sh` en hérite et ajoute l'événement JSON dans `~/.orbit/agent-events/<identifiant>.jsonl` (même mécanisme sur macOS, Linux et Windows). Pour un terminal ouvert par une ancienne version, sans identifiant, il retombe sur le PID du shell trouvé en remontant l'arbre des processus.
3. L'extension surveille ce dossier, met à jour l'état de l'agent, l'onglet (via `_orbit.setTerminalStatus`), la vue discussion et la barre Discussions.

## 8. Problèmes connus / pièges

- **Raccourcis dans un terminal** : VS Code envoie au programme du terminal tout raccourci dont la commande n'est pas dans `terminal.integrated.commandsToSkipShell`. Toute commande Orbit qui a un raccourci doit être ajoutée à `configurationDefaults` de `extensions/orbit/package.json` (c'est ce qui cassait Ctrl+V pour les captures). Tester un raccourci avec une vraie frappe, pas par la palette.
- **Icônes redessinées en boucle** : ne jamais réécrire le `innerHTML` d'un bouton sur un minuteur ; l'élément sous la souris disparaît entre l'appui et le relâchement et le clic n'arrive pas (bouton Lecture de StarCapture). Ne redessiner que quand l'état change.
- **Mettre à jour une extension seule** : `node extensions/orbit/esbuild.mts` (quelques secondes) produit `dist/extension.js` ; le copier avec `media/`, `control/` et `package.json` (`main` → `./dist/extension`) dans `resources/app/extensions/orbit` de l'installation, puis redémarrer Orbit. Pas besoin de la construction complète tant que le cœur ne change pas.
- **Installer sans fermer Orbit à la place de l'utilisateur** : `scripts/orbit-install-when-closed.ps1` (à lancer détaché) attend qu'Orbit soit fermé 20 secondes de suite, puis installe la construction en attente dans `..VSCode-win32-x64` ; journal dans `%TEMP%orbit-install-auto.log`. `scripts/orbit-extension-update.mjs` met à jour une extension seule, dans l'installation ou dans une construction en attente (`ORBIT_TARGET`).
- **Fenêtre de test bloquée par l'antivirus** : depuis le 8 octobre 2026, Windows Defender met en quarantaine `out/vs/workbench/contrib/chat/electron-browser/pluginGitCommandService.js` (fichier d'origine de VS Code, fausse alerte) dès qu'il est régénéré ; la fenêtre de développement ne démarrait plus. L'utilisateur a ajouté lui-même le dossier `orbit-ideout` aux exclusions de Defender (Claude Code refuse cette commande) ; sur une autre machine, c'est à l'utilisateur de le refaire.
- **Construction** : `gulp vscode-win32-x64-min` sature la machine (6 min, ~8 Go). Ne la lancer que sur demande de l'utilisateur ; `scripts\orbit-update.ps1 -SkipBuild` installe une construction déjà faite.

- ⌘K en édition inline masque les accords VS Code ⌘K X quand l'éditeur a le focus (comme Cursor).
- Les permissions de Claude dans la vue discussion envoient des touches au TUI (Entrée / « 2 » / Échap) : pas testé avec une vraie demande d'autorisation (la config de l'utilisateur est en « bypass permissions »).
- Un nouveau terminal Claude peut apparaître en double après un rechargement si les terminaux persistants reviennent tard (délai de 2,5 s dans `autoStart`).
- Le mode `acceptEdits` laisse Claude Code créer des dossiers (`mkdir`) sans demander — comportement du CLI.
- `vscode-file://` met parfois en cache l'ancien JS du cœur : redémarrer la fenêtre, pas juste Reload.
- Ne pas mettre de chemin long pour `--user-data-dir` (socket IPC trop long).
